# 上下文读取、用户授权和长期记忆隐私规格

## 目标

飞灵（FLGO） 的上下文和记忆能力必须默认可解释、范围清晰、操作可审计。系统可以帮助用户理解当前会话最近消息，但不能跨会话扩展上下文、长期保存正文或建立不可见的个人档案。

本规格覆盖后续上下文读取、用户授权、长期记忆、审计和删除策略。除非后续任务明确修改，本文件是相关实现的默认产品和工程边界。

## 默认配置

- `FCGO_CONTEXT_RECENT_MESSAGE_LIMIT=50`、`FCGO_CONTEXT_RECENT_TIME_WINDOW_HOURS=24`：最近聊天读取的数量和时间窗口。
- `FCGO_CONTEXT_CACHE_TTL_HOURS=24`、`FCGO_CONTEXT_CACHE_REFRESH_SECONDS=60`：最近聊天原文只做短期缓存，减少重复飞书 API 调用。
- `FCGO_CONTEXT_INJECT_MESSAGE_LIMIT=8`、`FCGO_CONTEXT_MAX_CHARS=6000`：每次模型请求优先注入近期全文消息，超过窗口或预算的旧消息压缩为当前会话摘要。
- `FCGO_MEMORY_STORE_RAW_TEXT=false`：默认禁止长期保存完整聊天原文、飞书正文或网页正文。长期记忆只能保存用户可查看、可编辑、可删除的结构化摘要或偏好。
- `FCGO_MEMORY_ITEM_MAX_CHARS=2000`、`FCGO_MEMORY_CONTEXT_MAX_CHARS=4000`：限制单条长期记忆内容长度，以及每次进入模型上下文的长期记忆总字符数。

这些默认值是开源安全基线。部署者可以在私有环境中调整，但产品文案和日志必须清楚说明风险。

## 私聊上下文

- 默认开启当前会话上下文读取。系统只读取当前私聊最近有限窗口内的消息；聊天历史读取使用应用权限 `im:message:readonly` 和 tenant token，读取失败时降级为无历史上下文继续回答。
- 最近聊天原文可以按 TTL 短期缓存，用于减少重复 API 调用；缓存不得进入长期记忆，到期应清理。
- 近期窗口内的消息以全文形式进入本次模型上下文；超过窗口或字符预算的旧消息会压缩为摘要。
- 若长期记忆开启，私聊旧消息摘要可以同步为用户可见、可删除的“会话摘要”长期记忆；不得保存完整聊天原文、消息 ID、发送人和时间戳等原始记录元数据。
- 私聊中可以按需搜索或读取用户授权范围内的飞书资料，但不能全量扫描云空间、知识库或长期索引所有资料。
- 私聊中的长期记忆只属于当前用户，不能被其他用户、群聊或会话隐式复用。

## 群聊上下文

- 群聊中只有用户 @ 机器人或通过菜单/命令明确触发时，才处理该消息。
- 默认只使用当前 @ 消息、当前消息显式包含的链接，以及当前群聊/话题内的有限上下文；聊天历史读取使用应用权限 `im:message:readonly` 和 tenant token。
- 若消息属于群聊话题，优先限制在当前话题；否则限制在当前群聊。
- 不跨群读取，不跨私聊读取，不读取未授权成员的私聊内容。
- 群聊上下文默认不沉淀为个人长期记忆。若模型识别到可能有用的个人偏好，必须引导用户在私聊中确认后再写入。
- 群聊会话摘要只属于当前群聊或话题，不应写入任何成员的个人长期记忆。
- 群聊中的会话级偏好只影响当前群聊或话题，不应覆盖任何成员的个人偏好。

## 资源读取

- 飞书文档、电子表格、多维表格和知识库内容只能在用户本人有资源权限、应用具备 API 权限、且 OAuth token 包含所需 scope 时读取。
- 私聊中没有显式链接、且用户明确要求搜索/读取飞书资料时，可以按需搜索用户本人可见的云文档；默认只搜索 `doc`、`sheet` 和 `bitable`，并受候选数和自动读取数上限约束。
- 普通网页链接只读取用户显式发送的 URL，并受超时、内容类型和大小限制约束。
- 资源正文只进入当前模型请求上下文，不写入 SQLite、不写入审计 detail、不输出到普通日志。
- 读取失败时返回可操作原因，例如需要 `/授权`、缺少 scope、无资源权限、内容过大或格式不支持。
- 资料搜索必须按需执行，不全量扫描云空间，不建立长期索引；审计只记录查询长度、类型、数量和结果计数，不记录完整搜索词或正文。

## 长期记忆

- 长期记忆只能保存结构化摘要或偏好，例如称呼、语言风格、输出格式、常用项目名称、用户手动确认的工作偏好。
- 不保存完整聊天原文、飞书正文、网页正文、附件正文或完整模型上下文。
- 私聊中超过近期窗口的旧消息可以压缩为“会话摘要”记忆；该记忆必须可查看、可删除、可关闭调用，并且不得包含完整聊天原文或原始记录元数据。
- 单条长期记忆和每次注入模型上下文的长期记忆总量必须受代码级字符上限限制。
- 记忆写入来源必须可区分：用户手动写入、用户确认模型建议、用户导入。
- 模型只能提出“是否记住”的候选建议，用户确认前不得写入长期记忆。
- 用户必须能查看、修改、删除、清空和关闭自己的记忆。关闭长期记忆只暂停新增和上下文调用，不清空已有记忆；后续模型上下文不得包含该用户的记忆。

## 审计和日志

- 审计日志可以记录事件类型、actor_id、会话/资源标识、provider、model、latency、usage、错误类别和操作结果。
- 审计日志不得记录完整聊天正文、飞书正文、网页正文、附件正文、OAuth token、API key 或 Authorization header。
- 错误信息必须脱敏后再写入日志或返回飞书用户。
- 与授权、上下文历史读取、会话摘要更新、记忆写入/修改/删除、资源搜索和资源读取相关的关键事件应写入审计日志。
- Agent 工具规划和执行审计只能记录工具名、是否执行、查询数量、查询长度、结果数量、资源类型和错误类型等元数据，不得记录用户原文、搜索词原文或模型思考过程。

## 删除和撤销

- 用户删除或清空长期记忆后，SQLite 中对应记忆内容应被删除或标记为不可用于上下文。关闭长期记忆不删除已有记忆，只暂停新增和调用。
- 用户重新授权 OAuth 时，旧 token 可以被替换；授权失败或过期时，应提示用户重新 `/授权`。
- 若未来引入向量索引或缓存，必须提供按用户删除的清理策略，并继续遵守 `FCGO_MEMORY_STORE_RAW_TEXT=false` 的默认边界。

## 后续实现要求

- `UXS-24` 应实现用户可见的授权、上下文状态查看、记忆查看/删除/关闭指令。
- `UXS-25` 到 `UXS-27` 的上下文读取和构建器必须遵守本规格的作用域、窗口和摘要边界。
- `UXS-28` 和后续记忆任务必须只保存结构化摘要/偏好，并提供完整 CRUD 和关闭能力。
- `UXS-29` 应补齐审计、删除策略和测试，确保正文不落库。
